\begin{frame}{1. Sledgehammer}
\note{
\begin{itemize}
  \item AI has been considered as a tool to improve theorem proving for a long time by now.
  \item The first and most impactful attempt was the development of Sledgehammer for Isabelle by Larry Paulson et al. \citep{paulson2010three}.
  \item Sledgehammer bridges interactive theorem proving with automated theorem provers (ATPs) and SMT solvers.
  \item Architecture: Fact Filter (MePo/MaSh) $\to$ TPTP/SMT-LIB $\to$ External Solvers (E, Vampire, Z3) $\to$ Proof Reconstruction in Isabelle Kernel.
  \item Live demonstration of Sledgehammer in Isabelle.
\end{itemize}
}

\begin{itemize}
  \item<1-> \textbf{First \& Most Impactful Automation Attempt:}
    \begin{itemize}
      \item \textbf{"Sledgehammer"} in Isabelle/HOL \citep{paulson2010three} (Paulson, Blanchette et al.).
      \item Bridges interactive theorem proving with external ATPs and SMT solvers.
    \end{itemize}
\end{itemize}

\begin{frame}{2. Custom Models for Formal Proving}
\note{
\begin{itemize}
  \item Proprietary systems initially dominated formal theorem proving by training custom models.
  \item Benchmarks like PutnamBench and the International Mathematical Olympiad (IMO) were considered mathematical holy grails.
  \item DeepMind developed AlphaProof by fine-tuning Gemini models with reinforcement learning (RL) search in Lean.
  \item Specialised startups like Harmonic (Aristotle) and Axiom Math (AxiomProver / AXLE) trained custom transformer policy and value models using RL feedback loops with theorem prover compilers.
  \item IMO Gold was achieved by AI in 2025 by DeepMind and Harmonic.
  \item PutnamBench 2025 is currently solved by at least 20 different proving systems.
  \item High compute and training cost: Base foundation pre-training costs \$5M--\$100M+, targeted RL stages cost \$250k--\$1M+ (e.g.\ DeepSeek-R1 $\approx \$294\text{k}$), and test-time search costs \$60--\$300+ per solved theorem.
\end{itemize}
}

\begin{itemize}
  \item<1-> \textbf{Key Players \& Breakthroughs:}

      \item \textbf{IMO Gold} achieved in 2025; \textbf{PutnamBench 2025} solved by $\ge 20$ proving systems.
    \end{itemize}

\begin{frame}{3. Democratisation via Agentic Proving}
\note{
\begin{itemize}
  \item Josef Urban and collaborators discovered that standard, off-the-shelf LLM coding agents are remarkably capable using simple batch builds (\texttt{isabelle build}).
  \item In a recent landmark experiment, standard coding agents formalised an entire 800+ theorem textbook on Topology (Munkres) for $\approx \$200$/month.
  \item Following this, subsequent work connected off-the-shelf agents via Model Context Protocol (MCP) servers for direct, interactive proving.
  \item Any student or researcher with a standard coding agent and a laptop can now formalise mathematics and software without multi-million-dollar training clusters.
\end{itemize}
}

\begin{itemize}
  \item<1-> \textbf{Off-the-Shelf Coding Agents (Batch Loop):}
    \begin{itemize}
      \item Josef Urban et al.\ showed standard coding agents (e.g.\ \emph{Claude Code}) formalised an entire textbook (\emph{Munkres Topology}, 800+ theorems) using simple \texttt{isabelle build} for $\approx \mathbf{\$200}$ \textbf{/ month}.
    \end{itemize}
  \vspace{0.6em}
  \item<2-> \textbf{Follow-up: Interactive Proving via MCP:}
    \begin{itemize}
      \item Subsequent work connects agents directly via \textbf{Model Context Protocol (MCP)}.
      \item Replaces batch CLI loops with rich, interactive kernel feedback (no cluster training needed).
    \end{itemize}
  \vspace{0.6em}
  \item<3-> \textbf{Practical Advantages:}
    \begin{itemize}
      \item No specialised GPU infrastructure or training required.
      \item Fast, interactive feedback loop directly with the Isabelle/HOL environment.
    \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{5. Agentic Proving Architectures}
\note{
\begin{itemize}
  \item The most basic agentic architecture for theorem proving consists of a Planner/Sketcher, a Coder, an MCP server, and Isabelle.
  \item Introduced in the "Draft, Sketch, and Prove" paradigm by Jiang, Li et al. \citep{wendaLiSketchProveLLMs}.
  \item The Planner/Sketcher produces detailed proof plans and sketches (e.g.\ sorried proofs).
  \item The Coder takes the proof plans \& sketches, completes them, and ensures Isabelle accepts them via MCP.
  \item If an error cannot be resolved by the Coder, it passes back to the Planner/Sketcher.
  \item Since the area is moving very fast, I will leave a paper on KEATS for you to read and discuss in the LGT.
\end{itemize}
}

\end{itemize}

\vspace{-0.3em}
\begin{itemize}
  \item<2-> \textbf{Two-Stage Workflow \& Feedback Loop:}
    \begin{itemize}
      \item \textbf{Planner / Sketcher:} Produces high-level proof sketches (\texttt{sorry}) \citep{wendaLiSketchProveLLMs}.
      \item \textbf{Coder:} Fills in intermediate Isar proof steps \& verifies against Isabelle via MCP.
      \item \textbf{Error Loop:} Unresolved errors pass back to the Planner with diagnostics.
    \end{itemize}
